# 智能陪伴桌宠框架

## 1. 定位

本框架参考常见“角色精灵 + 右键工具菜单 + 人设聊天 + 本地小游戏”桌宠产品的
功能分层，在 OnePic Desktop Pet 现有 PySide6、40 帧精灵、素材审批和隐私发布
体系上增加一层可复用能力。它不是第二套桌宠程序，也不复制参考商品的代码、角色
素材或文案。

默认继续使用 `rendering_mode=sprite`。智能聊天、人物档案、计时器和小游戏均不需要
Live2D；八向视线仍保持独立关闭，只有用户明确点名后才能进入素材制作流程。

## 2. 与参考方案的功能对照

| 能力 | OnePic 原有基础 | 本框架优化 |
|---|---|---|
| 透明置顶角色、拖拽、坐睡、摸头 | 已有 | 原样复用，不建立第二个动画状态机 |
| 多帧眨眼、张嘴、动耳或屏幕边缘姿态 | 已有扩展帧播放器 | 继续走版本、GIF、联系表、哈希和人工确认门禁 |
| 人设和用户档案 | 缺少 | 按 `pet_id` 存储，可查看、编辑和删除 |
| 实时聊天与 API 设置 | 原窗口明确不联网 | 可选 BYOK 的 OpenAI-compatible 适配器；默认关闭 |
| 历史和记忆 | 只有本地台词防重复 | SQLite 历史、可编辑记忆和显式选择发送范围 |
| 预设指令 | 可绑定本地动作台词 | 文本模板注册表；禁止 `eval`、命令或任意 URL 执行 |
| 番茄钟、正倒计时、整点报时、随机数 | 有 25 分钟专注核心 | 增加独立工具模型和 UI，并桥接已有庆祝动作 |
| 好感度 | 已有 `bond`、等级、金币和照料 | 只把归一化状态作为聊天语气上下文，不授权模型改存档 |
| 小游戏 | 缺少 | 首版提供可测试的扫雷模型和独立 Qt 窗口 |

## 3. 模块边界

```text
PetWindow（已批准动画与本地气泡）
  └─ CompanionController（菜单、窗口和白名单动作桥）
       ├─ framework.py  功能注册表与默认预设
       ├─ storage.py    SQLite 档案、历史、记忆、指令与设置
       ├─ secrets.py    按宠物和服务来源绑定的 Windows DPAPI 密钥
       ├─ chat.py       OpenAI-compatible 协议与安全动作提示解析
       ├─ qt_chat.py    可立即中止的 Qt JSON/SSE 网络适配
       ├─ tools.py      计时、报时与随机数纯逻辑
       ├─ games.py      扫雷纯逻辑
       └─ ui.py         PySide6 陪伴中心与独立工具窗口
```

模型输出只能产生展示文本和有限的 `happy`、`shy`、`wave` 等动作提示。动作提示必须
再次通过 OnePic 白名单；扩展动作只有已经出现在当前已审批运行清单中时才能播放。
任何模型文本都不能执行 shell、Python、文件操作、剪贴板写入、上传或任意 URL。

## 4. 数据与联网

- 档案、历史、记忆、预设和工具设置默认位于用户的
  `%LOCALAPPDATA%/OnePicDesktopPet/`，并按 `pet_id` 隔离；
- API 密钥不写入 SQLite、项目配置、日志或分享 ZIP，Windows 上使用当前用户 DPAPI
  加密；每份密文同时绑定 `pet_id` 和规范化服务 origin，换宠物或换服务时
  不会自动复用；加密不可用时拒绝落盘；
- 云端聊天默认关闭。用户发送消息时，传本轮消息、角色档案、用户档案、只读
  好感度、用户勾选的记忆、所选本次预设文本（如有）以及内置情绪/动作白名单；
  最近 30 条历史默认不发送，只在用户显式开启后携带；
  原图、自拍、动画帧和 `user_assets/` 永不上传；
- 每次请求固定绑定发起时的 `pet_id`；切换形象会取消旧请求，即使迟到回复
  也只能写回原宠物，不得污染新宠物档案或历史；
- Qt 网络适配不创建阻塞 `QThread`；取消、超时或应用退出会立即
  `QNetworkReply.abort()`；Qt 与标准库两条网络路径都拒绝自动 HTTP 重定向，
  Qt 请求还禁止 Cookie 读写和认证缓存复用，避免 Bearer 密钥或服务会话跨宠物传播；
- 自定义服务地址若不是 HTTPS 或本机 loopback，UI 必须提示风险；
- 服务地址含 `key`、`token`、`secret`、`password` 等敏感查询参数时拒绝保存，
  防止密钥绕过 DPAPI 进入 SQLite；
- UI 可导出当前宠物的本地陪伴数据（不含 API Key），也可经二次确认
  逐宠删除档案、历史、记忆、预设和工具设置；
- 陪伴数据库不可用或旧宠物 ID 不符合隔离规则时，可选陪伴层安全停用，基础桌宠
  继续运行；托盘显示不含路径或异常细节的不可用提示；
- 历史、记忆、档案、数据库、凭据密文和日志均不得进入公开或分享构建。

## 5. Android 智能陪伴 MVP

Android 端复用同一份已批准 `runtime/manifest.json` 与悬浮宠物状态机，但陪伴数据和
网络实现使用平台原生组件：

```text
CompanionActivity（设置、发送范围、本地历史与取消）
  ├─ CompanionSettingsStore  按 pet_id 保存非密钥设置
  ├─ CompanionSecretStore    Android Keystore AES-256-GCM 密钥
  ├─ CompanionStore          应用私有 SQLite 档案、记忆与消息
  ├─ CompanionEndpoint       HTTPS 端点规范化与来源绑定
  └─ OpenAiCompatibleClient  可取消的非流式 JSON 请求
       └─ CompanionReplyParser → PetOverlayService 动作硬白名单
```

- 打开陪伴页、编辑或保存本地档案都不会联网；只有云聊天开启且用户点击发送才请求；
- Android 悬浮角色默认使用系统手势阈值：确认单击后播放本地互动，双击直接打开
  陪伴页，拖拽优先且不会误触聊天；该入口不等于开启云聊天；
- 角色人设随云聊天请求发送；用户档案、记忆和最近历史分别默认关闭，必须显式勾选；
- API Key 不进入 SQLite，Keystore 密文以 `pet_id + origin` 作为 AES-GCM AAD；
- 端点只允许 HTTPS，拒绝凭据、查询参数、片段、相对路径段和重定向；
- 历史最多取最近 30 条，并限制 24,000 字符；响应读取上限 1 MiB、可见上限
  12,000 字符；
- 设置页使用 `FLAG_SECURE`；应用私有数据同时排除 Android 云备份与设备迁移；
- 模型只能在纯文本末尾建议一个当前宠物已装配的白名单动作，不能执行工具、URL、
  shell、文件、剪贴板或设备操作；
- 首版为文字、非流式 MVP，不包含语音、图片、后台主动消息、预设工具和小游戏。

Windows 与 Android 不共享用户档案、聊天历史或 API Key；只共享已批准的角色运行
素材与动作命名，避免跨设备同步在未得到用户授权时扩大数据边界。

## 6. 发布与验收

框架代码继续由现有单元测试和源码烟测覆盖。新增角色动作时仍需素材、行为、配置、
流程和窗口测试以及用户视觉验收；框架自动测试不能替代动作验收。

发布仍只允许使用 `scripts/release_pet.ps1` 生成完整目录 ZIP，不单发 EXE。发布检查
必须确认包内不存在数据库、聊天记录、人设、记忆、API 密钥、私人图片或本机绝对
路径；扫描会显式拒绝 `.sqlite`、`.sqlite3` 和 `.dpapi` 文件、伪装后缀的
SQLite/DPAPI 文件头，以及任意盘符或 UNC 本机绝对路径。
源码与成品发布烟测还会分别重定向 `ONEPIC_COMPANION_DATA_DIR`，不会读取、播种或
修改用户真实的陪伴数据库和密钥目录，脚本退出时恢复原环境值。
