# OnePic 跨平台桌宠复用框架

## 支持范围

当前框架以同一份已批准的精灵运行包生成两个客户端：

- Windows：Python + PySide6 透明桌面窗口，正式分享物为完整目录 ZIP；
- Android：原生 Java 悬浮窗，正式分享物为 Release 签名 APK。

两端共用 `user_assets/pets/<pet-id>/runtime/manifest.json` 和其中明确引用的透明
PNG，但不共用平台代码。macOS 和 iOS 客户端尚未实现，不能把现有构建称为四端
通用包；后续可以继续复用相同的运行清单和审批记录。

智能陪伴也采用“共享行为契约、平台本地存储”的方式：

| 边界 | Windows | Android |
|---|---|---|
| 密钥 | 当前用户 DPAPI | Android Keystore AES-256-GCM |
| 档案与历史 | `%LOCALAPPDATA%` 下按宠物 SQLite | 应用私有 SQLite/SharedPreferences |
| 网络 | 标准库或 Qt JSON/SSE | 原生 `HttpsURLConnection` 非流式 JSON MVP |
| 动作联动 | 现有 `PetWindow` 白名单 | `PetOverlayService` 当前素材白名单 |
| 跨端同步 | 不自动同步 | 不自动同步 |

两端云聊天都默认关闭，用户档案、记忆和历史均按显式发送范围处理；Android 端额外
禁止陪伴页截图，并把陪伴数据排除系统备份。当前没有 iOS 版，也没有把 Windows 的
本地工具和小游戏冒充成 Android 已支持能力。

## 不会被下一只宠物覆盖的内容

- 每只宠物拥有独立的 `user_assets/pets/<pet-id>/`；
- 原图、候选、动作、走路、审批和备份不会与其他宠物混放；
- Android 工程只接收运行清单引用的 PNG，不复制原图、自拍、候选或备份；
- 已有演示应用继续使用既有包名 `com.onepic.desktop.pet`；
- 新宠物默认得到 `com.onepic.desktop.pet.<pet-id>` 形式的独立包名，短横线会
  转换成下划线，因此可以和已有演示应用同时安装。

Android 的应用包名是永久身份。某只宠物首次正式发布后，不要更改其包名；升级时
提高 `VersionCode`，并继续使用同一 JKS、别名和密码。

## 制作下一只宠物

先创建独立工作区：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\new_pet.ps1 `
  -PetId "next-pet" `
  -DisplayName "下一只桌宠" `
  -Source "图片或视频的完整路径" `
  -RenderingMode sprite
```

继续执行标准角色确认、八相位走路确认和素材 QA。两个确认门禁都通过后，可一次构建
Windows 本地运行版和 Android Debug APK：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass `
  -File .\scripts\build_cross_platform_pet.ps1 `
  -PetId "next-pet" `
  -DisplayName "下一只桌宠" `
  -AndroidApplicationId "com.onepic.desktop.pet.next_pet" `
  -VersionCode 1 `
  -VersionName "0.1.0"
```

不传 `AndroidApplicationId` 时，脚本会根据 `PetId` 安全生成；正式发布前仍建议
把最终包名记录下来。构建输出还会生成 `onepic-build-report.json`，记录包名、
版本、APK 文件名、大小和 SHA-256。

## 正式双端发布

Windows 分享版必须继续通过：

```powershell
.\scripts\release_pet.ps1 -PetId "next-pet" -Mode share-no-selfie
```

Android 正式包可以运行 `tools/OnePicReleaseSigner.exe`：

1. 填写宠物 ID、显示名称、永久应用包名和版本；
2. 选择已有 JKS，或选择一个不存在的新路径创建 JKS；
3. 使用已有 JKS 时填写它原来的别名和密码；
4. 点击 `Build signed APK`；
5. 分享形如 `next-pet-0.1.0-release.apk` 的命名文件。

签名窗口不会保存密码。JKS 和密码应分别保留至少两份安全备份；同一个应用包名的
后续升级必须继续使用相同签名。不同宠物可以共用同一发布密钥，也可以按发布策略
使用不同密钥。

也可以在当前 PowerShell 进程中设置四个 `ONEPIC_ANDROID_*` 签名变量后运行：

```powershell
.\scripts\build_android.ps1 `
  -PetId "next-pet" `
  -DisplayName "下一只桌宠" `
  -ApplicationId "com.onepic.desktop.pet.next_pet" `
  -VersionCode 1 `
  -VersionName "0.1.0" `
  -Configuration Release
```

## 每次新宠物仍然必须重新验收

框架可以复用，角色审批不能复用。每只新宠物都必须：

1. 登记来源并选择画风；
2. 只生成一张标准角色候选并由用户确认；
3. 制作八相位走路和两张摸头过渡帧；
4. 展示走路 GIF 并由用户确认；
5. 运行素材、行为、配置、流程和窗口测试；
6. 分别完成 Windows 与 Android 真机视觉验收；
7. 发布前执行隐私扫描，并确认包内没有原图和本机绝对路径。

八向视线、Live2D 和进阶动作仍是明确点名后才加入的选配能力，不会因复用框架而
自动启用。
