# VPet 养成层落地报告

## 结论

VPet 类养成玩法应作为 OnePic Desktop Pet 的可选领域模块接入，不应另建一套
角色制作框架。现有 38 帧基础配方、两张摸头过渡帧、扩展动作、审批、隐私、
Windows 与 Android 装配流程继续作为唯一素材和发布底座。

## 模块边界

- `care.py`：维护养成数值并输出需求压力，不创建窗口、不读取素材；
- `behavior.py`：把需求压力映射到现有 `idle/walk/sit/sleep/selfie` 状态；
- `window.py`：负责按真实时间推进、照料入口与摸头互动，不保存角色素材；
- `runtime/manifest.json`：声明某只宠物是否启用养成玩法及平衡参数；
- `workflow.json`：用规范化配置 SHA-256 绑定用户确认，参数变化即使旧确认失效；
- Windows 用户存档：按 `pet_id` 保存到本地设置目录，不写入工作区或分享包；
- Android 用户存档：写入应用私有 `SharedPreferences`，不使用外部存储或网络。

## 已完成范围

框架默认仍关闭养成；演示配置可通过宠物清单显式启用。当前状态包括饱腹、饮水、
活力、心情、健康、好感、经验、等级和金币，并提供：

- 喂小点心：消耗金币，提高饱腹、少量心情和经验；
- 喝水：消耗金币，提高饮水和少量经验；
- 一起玩：消耗活力，提高心情、好感和经验；
- 休息：复用已批准的 `sleep/sit`，暂停移动并恢复活力；
- 摸头：沿用既有触摸过渡，提高心情和好感；
- 专注陪伴：复用 `focus_work`，完成后奖励金币和经验；
- 自主行为：低活力等需求通过标准化压力影响既有行为状态机；
- Windows 与 Android：共用同一配置语义，但分别保存在各自应用私有存储中。

## 当前不包含

- VPet 代码、存档或美术素材复制；
- 带图片的商店、背包、物品库存和复杂工作系统；
- Live2D、八向视线或新的角色动作；
- 未经用户视觉确认的素材生成和激活。

## 演示产品参数

- 初始金币 60；
- 点心 8 金币、恢复 24 饱腹；
- 喝水 2 金币、恢复 28 饮水；
- 玩耍消耗 6 活力、增加 14 心情；
- 专注完成奖励 18 金币、10 经验；
- 操作冷却 900 ms；
- 配置确认哈希：
  `cae9aa3cfedcbe043e5f445be912719bb19615b67de6ba787e3fd66f4a8b4f8c`。

## 后续可选扩展

如用户继续点名，可在不改变素材底座的前提下增加物品库存、任务、成就或数据迁移。
需要新图片或新动作的扩展仍必须单独生成 GIF、联系表和哈希报告，并重新视觉确认。

## 许可证边界

VPet 程序代码使用 Apache-2.0，但其动画和第三方素材具有独立授权要求。本试验
仅参考公开的领域概念和模块边界，Windows 使用 Python/PySide6、Android 使用
原生 Java 独立实现，不导入 VPet 源码、二进制、存档或素材。
